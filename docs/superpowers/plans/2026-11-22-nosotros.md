# Página Nosotros Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crear `/nosotros` y `/en/about`: hero dividido con la foto grupal, franja de datos, grilla de 5 retratos ("Asesor 1…5"), 4 valores y el CTA del Home.

**Architecture:** Igual que el Home: un orquestador `AboutPage.astro` (prop `lang`) compone componentes de sección en `src/components/about/`, cada uno con su objeto `t` inline ES/EN. Los datos del equipo viven en `src/config/team.ts`. Las fotos se generan una vez con un script `sharp` desde `../datams/team/` a WebP en `src/assets/images/team/` y se sirven con `astro:assets`.

**Tech Stack:** Astro 6, Tailwind 4 (tokens de `global.css`), Vitest + Container API, sharp 0.34 (ya instalado vía Astro).

**Spec:** `docs/superpowers/specs/2026-11-22-nosotros-design.md`

## Global Constraints

- Colores/tipografía/fluid actuales: tokens (`brand`, `brand-light`, `neutral-dark`, `neutral-grey`, `cream`, `background-light`…), `text-fluid-*`, `.title`, `.btn .btn-primary`, `font-display`. Nada de hex hardcodeado.
- Un solo `<h1>` por página (el del hero). `lang` del `<html>` lo pone `BaseLayout`.
- Prohibido en ES/EN: "certificado/certified", "Realtor", "notario/notaría/notarial", "licenciado", "abogado" como oferta.
- Cargo de todos los asesores: **"Tax Preparer"** (igual en ES y EN, como en sus placas). Nombres: **"Asesor N"** / **"Advisor N"**.
- Personas de los slides 3 y 4 del hero (IA): no usar.
- Breakpoints: mobile first, `sm` 640, `md` 768, `lg` **990**, `xl` 1280. Touch targets ≥44px.
- Imágenes: WebP, `alt` descriptivo, `loading="lazy"` salvo la del hero (`loading="eager"`, `fetchpriority="high"`).
- Foto grupal: nunca mayor que su ancho real (1024px): `widths` máximo 1024.
- **Commits:** el usuario commitea solo cuando lo pide (memoria `feedback-no-commits`). Cada tarea termina con "reportar diff"; los mensajes sugeridos se usan si el usuario pide commitear (commits secuenciales por tema).

## Review Focus

1. **Placa de Professional Multiservices** visible en el retrato del Asesor 3 tras el parche → el texto de la placa no debe leerse a ningún tamaño (verificación visual en Task 1).
2. **320px de ancho**: la franja de datos y la grilla no deben generar scroll horizontal (el Home ya tiene ese bug con "5,000+") → test de clases + check visual en Task 5.
3. **Switch de idioma** en `/nosotros` debe llevar a `/en/about` (no a `/en`) → test en Task 2.
4. **Cuántas tarjetas**: si alguien agrega la 6ª persona a `TEAM`, la grilla debe seguir cuadrando (5 cols en xl → 6 hace fila de 1) → la grilla usa `flex flex-wrap justify-center`, test en Task 3.
5. **Lector de pantalla**: el nombre de cada tarjeta es encabezado (`h3`) bajo un `h2` de sección; sin saltos de nivel → test en Task 3/4.
